# Evaluo P1 — Seguimiento de infraestructura (25/10/2026)

## Definición de flujo

- `seo_public`: `/pregunteros`, `/simulador`, `/explorar`, `/universidad`. **No sumar como uso educativo basado en PDF.**
- `pdf_private`: `/api/student-materials`, `/api/internal/student-material-jobs`, `/dashboard/materiales` y scopes `processStudentMaterial.*` / `pedagogy.*`.
- `other`: resto. No inferir que `/dashboard` genérico representa una práctica sobre PDF.

Next.js `instrumentation.ts` etiqueta las excepciones de solicitud; `lib/observability.ts` etiqueta los scopes existentes. Los logs estructurados no incluyen claves ni respuestas del proveedor. `student_material_processing_ready` agrega `metadata.flow=pdf_private` en el evento YA EXISTENTE; no se escribe ningún evento extra en Supabase.

## Consultas reproducibles (Supabase Unified Logs)

Para un día de Argentina, pasar al conector `query_logs` el inicio 00:00 -03:00 y fin 00:00 -03:00 del día siguiente, convertidos a UTC; máximo 24h. Ejemplo del 24/10/2026: `2026-10-24T03:00:00Z` a `2026-10-25T03:00:00Z`.

```sql
SELECT
  multiIf(
    event_message LIKE '%/preguntas_banco_public%' OR
    event_message LIKE '%/get_public_preguntero%' OR
    event_message LIKE '%/grade_simulator_question%',
      'seo_public',
    event_message LIKE '%/student_material%' OR
    event_message LIKE '%/study_error%',
      'pdf_private',
    'other'
  ) AS flow,
  count() AS requests,
  countIf(match(event_message, '^[A-Z]+ [|] [45][0-9][0-9] [|]')) AS http_errors
FROM logs WHERE source = 'edge_logs'
GROUP BY flow ORDER BY requests DESC;
```

```sql
SELECT count() AS timeout_messages, min(timestamp) AS first_seen, max(timestamp) AS last_seen
FROM logs
WHERE source = 'postgrest_logs'
  AND event_message LIKE '%Thread killed by timeout manager%';
```

**Importante:** PostgREST no aporta ruta/request ID en esos eventos; NO atribuir los timeouts directamente a SEO ni PDF mediante una unión por timestamp. Comparar tendencias antes/después y latencia de endpoints conocidos, no afirmar causalidad.

## SQL acumulado (NO métricas diarias)

`pg_stat_statements` es acumulativo desde el último reset, así que sus `calls` NO son un conteo diario. Priorizar el tiempo total y los queries de `preguntas_banco_public`, sin usar ese agregado como prueba de un fallo específico.

- `nvidia/nemotron-3-super-120b-a12b` se excluye de la selección mientras devuelva HTTP 404 (modelo de respaldo previamente configurado). El principal verificado permanece.
- El monitor ignora la ausencia de `GROQ_API_KEY_FALLBACK` (opcional), pero registra `report.capabilities.pdfGroqConfigured`; `false` indica redundancia reducida, no una caída de credenciales configuradas.
